# Instant-Memory

Instant-Memory is a MongoDB-first personal memory pipeline with asynchronous synchronization to Pinecone and Neo4j.

## Architecture

1. The latest user message is classified by `MemoryDecision`.
2. MongoDB is the source of truth for extracted memories.
3. Each Mongo write creates an outbox event.
4. A per-user background worker synchronizes the event to Pinecone and Neo4j.
5. Pinecone handles semantic retrieval; Neo4j handles relationship and multi-hop retrieval.
6. Placeholder resolution updates MongoDB first, then refreshes the derived stores.
7. Every persistent store is scoped by `user_id`.

## Run

Create a `.env` file containing the required MongoDB, Pinecone, Gemini, NVIDIA, and Neo4j credentials.

Install dependencies with uv, then run:

```bash
uv run python main.py --user-id user_125
```

Run tests:

```bash
uv run pytest
```

## Important invariants

- MongoDB is the source of truth.
- Never query or mutate a memory without its `user_id` scope.
- Outbox failures use `error` and remain retryable.
- Neo4j relationship properties contain `memory_id` and temporal metadata.
- Relationship and label identifiers are validated before being interpolated into Cypher.
- Placeholder completion is scoped to the exact placeholder name.
- Generated bytecode, virtual environments, and secrets are not committed.

## Data flow

```text
User message
    |
    v
MemoryDecision
    |
    +---- retrieval ----> Pinecone / Neo4j ----> answer context
    |
    +---- saving -------> MongoDB ---> Outbox ---> Pinecone
                                             \--> Neo4j
```
